# เนื้อหาต้นฉบับ (ถอดความ)

## หน้า 1 — จากของที่มีอยู่ สู่ธุรกิจที่ทำซ้ำและสะสมความได้เปรียบ

STRATEGIC PORTFOLIO / 01

รายงานศึกษาตั้งต้น 6 Strategic Bets • SGAM เป็นศูนย์กลาง • ผู้รับหลัก: Group COO และเจ้าภาพธุรกิจ

> **ข้อเสนอหลัก: อนุมัติตรวจฐานและคัดโอกาสต่อยอด** ไม่ใช่อนุมัติสร้างหกธุรกิจหรือแพลตฟอร์มใหม่พร้อมกัน

### สิ่งที่เปลี่ยนจากการมอง “เทคโนโลยีใหม่”

เริ่มที่ **งานจริง ลูกค้าเดิม ระบบเดิม และทีมบริการ** แล้วหาว่าส่วนไหนต่อยอดเป็นข้อเสนอที่มีผู้จ่ายและทำซ้ำได้

ใช้ตัวอย่างโรงงานหนึ่งแห่งเชื่อม **TMS → PEMS → การปรับงาน → บริการ** โดยยังไม่ถือว่าระบบเชื่อมกันแล้ว

### คำถามที่รายงานนี้ต้องตอบ

ขายอะไร • ใครจ่าย • อยู่ส่วนไหนของห่วงโซ่ • ถืออะไรเอง • Partner อะไร • ผลประโยชน์ร่วมเกิดจริงอย่างไร

คำว่า “มีผลิตภัณฑ์” แยกจาก “มีผู้ใช้ active” และ “มีธุรกิจที่มีกำไร” เสมอ

### A / AMI

ตรวจฐานและสิทธิบริการจากงานปัจจุบันก่อน

### B + D / โรงงาน

ใช้ TMS–PEMS เป็นภาพร่วม แล้วเลือกหนึ่งปัญหาทดลอง

### C / Data Center

ติดตามคำขอเสนอราคาและคุณสมบัติตามจังหวะลูกค้า

### E / ข้อมูลร่วม

พัฒนาตามงานที่จำเป็นจริง ไม่สร้างใหญ่ล่วงหน้า

### F / Fleet

ศึกษาจากลูกค้ากองรถและ Partner ก่อนสร้างซอฟต์แวร์

### ส่วนบริหารร่วม

เชื่อมลูกค้า–ความรู้–บริการ–ผู้รับงาน–ผลลัพธ์

> **ข้อจำกัดที่ยังต้องเปิดไว้** ยอดขาย/กำไร/ฐานติดตั้งและสิทธิในระบบของแต่ละ Bet ยังไม่ได้รับการยืนยันจากสัญญาและข้อมูลการเงินภายใน

**แผนที่อ่าน:** อ่านฐานและการคัดเลือกก่อน → บท A–F → ความสามารถร่วม/Partner/มาตรฐาน → เงิน–Gate–ความเสี่ยง–แบบรับข้อมูล • ท้ายเล่มแหล่งอ้างอิง

**ฐานอ้างอิง:** [F01] PCC SGAM Strategic Architecture V1 · [F02] PCC Smart Grid Master Portfolio V1 · [F03] PCC Energy Data Platform Business Study V1 · [F04] PEM-F40-Base-Plan-60m

## หน้า 2 — QC ก่อน Insight: เรารู้อะไร และยังไม่รู้อะไร

STRATEGIC PORTFOLIO / 02

สถานะข้อมูล ณ 28 กันยายน 2569 • การค้นเว็บไม่ใช่การตรวจรับงานหรือสอบทานงบภายใน

### V-PUB — ตรวจพบการเผยแพร่

ยืนยันว่าบริษัท/หน่วยงานเผยแพร่สิ่งใด ไม่ยืนยันผลขายจริงโดยอัตโนมัติ

### M — ข้อมูลผู้ใช้

สิ่งที่ผู้ใช้เห็น/เล่า และความไม่แน่ใจที่ต้องรักษาไว้

### H / U — ข้อเสนอ / ยังไม่รู้

ข้อวิเคราะห์แยกจากช่องว่างหลักฐาน; ข้อมูลไม่พบไม่เท่ากับไม่มีธุรกิจ

| **C · Data Center**<br>PCC มีขอบเขตระบบไฟ [W03]; ไม่ยืนยัน DC reference | RFQ/AVL/reference, scope/ค่าปรับ/เงินทุน | โครงการ/วันซื้อ + ผู้เขียนสเปก + qualification + cash |

## หน้า 3 — ตรวจว่า “ธุรกิจยัง Active แค่ไหน” ด้วยหลักฐาน ไม่ใช่ชื่อผลิตภัณฑ์

STRATEGIC PORTFOLIO / 03

วิธีสำรวจที่เสนอ • เจ้าภาพแต่ละ Bet ส่งงานเดิม ไม่ต้องเริ่มทำสไลด์ขายแนวคิดใหม่

01 · มีประกาศ/ผลิตภัณฑ์ → 02 · สาธิต/ทดลองได้ → 03 · มีสัญญาและส่งมอบ → 04 · มีผู้ใช้/ทีมดูแล → 05 · ต่ออายุและสร้างกำไร

| คำถามตรวจสถานะ | หลักฐานที่ขอ | ข้อสรุปที่ยังห้ามกระโดด |
|---|---|---|
| มีอะไรอยู่จริงและใครดูแล? | ทะเบียนระบบ/รุ่น ผู้รับผิดชอบ demo ล่าสุด และวันที่อัปเดต | เว็บไซต์มีสินค้า ≠ ระบบยังได้รับการพัฒนา |
| ใครซื้อ ใครใช้ ที่ไหน? | สัญญา/PO/ตรวจรับ + สถานที่ + ผู้ใช้ที่ติดต่อได้ | สาธิตสำเร็จ ≠ ลูกค้ายอมจ่าย |
| ใช้งานและบริการต่อจริงไหม? | usage/incident/work order/การต่ออายุย้อนหลัง | ติดตั้งแล้ว ≠ ใช้งาน active |
| เกิดรายได้ กำไร และเงินสดไหม? | ยอดตามขอบเขตเดียวกัน ต้นทุนคน/license/cloud/support/warranty | ยอดขาย ≠ กำไร; ค่าบริการ ≠ กำไรประจำ |
| นำไปทำงานรายถัดไปได้ไหม? | connector/template/test/playbook และเวลาที่ใช้จริงรายใหม่ | มี source code ≠ มีผลิตภัณฑ์ที่ทำซ้ำคุ้ม |
| ถือสิทธิอะไร? | IP/API/export/data processing/maintenance/termination clauses | พัฒนาร่วม ≠ เป็นเจ้าของทั้งหมด |

### ช่วงข้อมูลที่เสนอขอ

ย้อนหลัง 12 เดือนล่าสุด + โครงการสะสมที่ยังดูแลอยู่ ระบุช่วงเวลาจริง หากดึงไม่ครบให้ส่งข้อจำกัด ไม่ประมาณแทน

### เจ้าภาพ / ผู้ทวนสอบ

เจ้าของงานให้ฐานจริง; การเงินตรวจเงินและการนับซ้ำ; วิศวกรรม/IT ตรวจ capability; กฎหมายตรวจสิทธิ; COO รับข้อเสนอ

## หน้า 6 — ขนาดตลาดต้องเริ่มจากผู้ซื้อที่เข้าถึงได้ ไม่ใช่ขนาดระบบไฟทั้งประเทศ

STRATEGIC PORTFOLIO / 06

ยังไม่ยืนยันมูลค่า TAM / SAM / SOM เป็นเงินบาทสำหรับหก Bet • ใช้สูตรและฐานนับที่ทีมกลับมาเติมได้

### สัญญาณตลาด Data Center

**42 โครงการ / 3,400 MW IT Load** คือชุดอนุมัติส่งเสริมปี2567–2569 ที่ BOI รายงาน [W07]

ไม่ใช่ก่อสร้างเสร็จ ไม่ใช่กำลังเชื่อมต่อไฟโดยตรง และไม่ใช่ขอบเขตงานของ PCC

### Solar: เป้าหมาย ≠ เปิดจริง

ร่างแผนกล่าวถึง **10,000 MW** [W08]; ประกาศรอบรับซื้อ PEA ระบุไม่เกิน **500 MW** [W09]

เป็นคนละขอบเขต/สถานะ ไม่ใช้20,000 MW หรือจำนวนบ้านคูณค่าระบบเป็นตลาดที่ยืนยัน

### Direct PPA: เงื่อนไขอนาคต

รายงานเดิม F03 อ้างร่างสำหรับ Data Center; ชุดนี้ยังไม่ยืนยันกติกาเปิดใช้ฉบับสุดท้าย

ไม่ใช้รายได้ settlement/VPP เป็นฐาน และไม่สรุปว่าต้องซื้อแพลตฟอร์มใหม่ทุกแห่ง

| Bet | หน่วยนับและการแปลงเป็นรายได้ที่เสนอ | ตัวกรอง SAM / SOM |
|---|---|---|
| A | ระบบ/สัญญาที่เข้าถึงได้ × ส่วนบริการที่ซื้อเพิ่ม × ราคาต่อระบบ/ปี; งานติดตั้งนับแยก | สิทธิระบบ/สัญญาและวงจรจัดซื้อ |
| B | เครื่อง/สถานที่เสี่ยงที่เข้าได้ × อัตราซื้อบริการ × ค่าบริการต่อเครื่อง/ปี; sensor/install แยก | ความเสี่ยงสินทรัพย์ + ลูกค้ายอมจ่าย |
| C | โครงการที่กำลังจัดซื้อและเข้า spec ได้ × ขอบเขตที่เสนอได้; ไม่เอาเงินลงทุน DC ทั้งหมดเป็น TAM | กำหนดซื้อ + AVL + scope + กำลังส่งมอบ |
| D | โรงงาน/ไลน์ที่มีปัญหาเฉพาะ × อัตราซื้อ × ราคาแพ็กเกจ + บริการ; ไม่นับ ERP ทั้งองค์กร | ปัญหาเฉพาะ/ข้อมูลฐาน/การหยุดเครื่อง |
| E | บัญชีผู้ซื้อไม่ซ้ำ × ราคาโมดูล/ปี + integration; ไม่คูณ MW แล้วเรียกยอดตลาดซอฟต์แวร์ | account ไม่ซ้ำ/สิทธิ/API/ต้นทุนเชื่อม |
| F | depot ที่พร้อมใช้ × package ที่รับได้ + บริการ; ไม่เอารถ EV ทั้งประเทศคูณค่าซอฟต์แวร์ | ตารางรถจริง/กำลังไฟ/ผู้จ่าย |

> **กติกานับตลาด** TAM = ผู้ซื้อในขอบเขตที่นิยาม • SAM = ส่วนที่เข้าได้ตามสินค้า/กติกา • SOM = ส่วนที่ขายและส่งมอบได้จริงตามเวลา; ไม่รวมยอดขายเดียวซ้ำใน B/D/E และแยกค่าติดตั้งจากค่าบริการรายปี

## หน้า 7 — A / จากระบบมิเตอร์ สู่บริการข้อมูลและดูแลต่อเนื่อง

### ลูกค้า / คุณค่าที่ขาย

**ผู้จ่ายที่ควรทดสอบ:** การไฟฟ้า/เจ้าของระบบมิเตอร์; ฝ่ายระบบไฟฟ้า–IT–จัดซื้อร่วมกำหนดงบ

**ข้อเสนอขาย:** เชื่อมข้อมูลมิเตอร์ให้ระบบเดิมใช้ได้ถูกต้อง ดูแลข้อผิดพลาดและการเปลี่ยนรุ่นหลังส่งมอบ

**ของเดิม:** PCC ประกาศ AMI ในขอบเขต Intelligent Grid [W03]; PEA มี HES/MDM/NMS อยู่แล้ว [W05]

**ข้อมูลผู้ใช้ (ยังไม่ยืนยัน):** ผู้ใช้ระบุว่ากำลังทำ AMI และทำ MDMS ร่วม Hitachi; รายได้บริการหลังส่งมอบยังไม่ทราบ [U01]

### ตำแหน่งเชิงกลยุทธ์ที่เสนอ

ศึกษาบริการส่วนที่ระบบเดิมหรือสัญญาเดิมยังไม่ครอบคลุม ไม่ขาย VEE ซ้ำโดยไม่รู้ว่าใครทำอยู่

**ควรถือ:** วิศวกรรมมิเตอร์ + ส่วนเชื่อม/ชุดทดสอบ + ความรู้การแก้ข้อมูล + บริการลูกค้า

**Partner:** ใช้ HES/MDMS เดิมเมื่อเหมาะสม; cloud/cyber/สื่อสารตามข้อกำหนด

### วิธีสร้างความได้เปรียบ

สะสมตัวเชื่อมและกรณีทดสอบหลายรุ่น + คู่มือแก้เหตุจริง → เปลี่ยนระบบเร็วและผิดพลาดน้อยลง

**ใช้ร่วม:** E ส่วนเชื่อม/คุณภาพข้อมูล; B ทะเบียนอุปกรณ์; ทีมบริการและความรู้หน้างาน

### ฐานเงินที่ต้องหามาเติม

ค่าติดตั้ง/วิศวกรรม/สินค้า แยกจากค่าบริการต่อเนื่อง; ตรวจต้นทุนคน license/cloud support อะไหล่ และรับประกัน

**หน่วยนับ:** ระบบ/สัญญาที่เข้าถึงได้ × ส่วนบริการที่ซื้อเพิ่ม × ราคาต่อระบบ/ปี; งานติดตั้งนับแยก

> **อะไรจะทำให้เปลี่ยนคำแนะนำ?** ไม่มีสิทธิข้อมูล/งบแยก หรือผู้ขายเดิมครอบคลุมครบ → กลับไปขาย integration/service ในสัญญาหลัก

**ไม่ทำตอนนี้:** ไม่สร้าง MDMS ใหม่เพียงเพื่อให้เป็นของตน และไม่ถือว่าข้อมูลของการไฟฟ้าเป็นของ PCC
