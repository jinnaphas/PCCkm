# เนื้อหาต้นฉบับ (ถอดความ)

## บอร์ด 1 — 6 กรอบอ้างอิง • รากฐานการเปลี่ยนงานด้วย AI

TEACHING BOARD 01

แยก “กรอบวิจัย / แนวทางออกแบบ / หลักการ / มาตรฐานระบบบริหาร” ก่อนนำมาสังเคราะห์

### MIT CISR [S1]

Enterprise AI Maturity • กรอบวิจัยระดับองค์กร

1. Experiment and Prepare — ทดลองและเตรียมองค์กร
2. Build Pilots and Capabilities — ทดลองใช้และสร้างความสามารถ
3. Develop AI Ways of Working — เปลี่ยนวิธีทำงานด้วย AI
4. Become AI Future Ready — พร้อมสร้างคุณค่าใหม่ด้วย AI

**PCC หยิบใช้:** พัฒนาคนและวิธีทำงาน ก่อนขยายแพลตฟอร์ม

### Microsoft HAX [S2]

Human–AI Interaction • แนวทางออกแบบ 18 ข้อ

- **เริ่มใช้** — บอกความสามารถและข้อจำกัด
- **ระหว่างใช้** — ช่วยให้ถูกงานและถูกจังหวะ
- **เมื่อ AI ผิด** — แก้ไข ปฏิเสธ และควบคุมได้
- **เมื่อใช้ต่อเนื่อง** — รับข้อเสนอแนะและแจ้งการเปลี่ยนแปลง

**PCC หยิบใช้:** คนกำกับ AI และแก้ข้อผิดพลาดได้จริง

### Stage-Gate® [S3]

กรอบพัฒนานวัตกรรม • แยกช่วงทำงานกับจุดตัดสินใจ

ค้นหาโอกาส → ผ่านด่านก่อนแต่ละช่วง

แนวคิด ◆ เหตุผลลงทุน ◆ พัฒนา ◆ ทดสอบยืนยัน ◆ นำไปใช้

เดินต่อ / หยุด / พัก / กลับไปปรับ • ทำซ้ำได้

**PCC หยิบใช้:** หลักฐาน → การตัดสินใจ → ทรัพยากรขั้นถัดไป

### NIST AI RMF 1.0 [S4]

กรอบบริหารความเสี่ยง AI • ใช้ตามบริบทและความเสี่ยง

- GOVERN (กำกับดูแลทุกส่วน) — กรอบครอบทั้งสามส่วนด้านล่าง
  - MAP — เข้าใจบริบท ↔ MEASURE — ประเมินความเสี่ยง ↔ MANAGE — จัดการความเสี่ยง

ทำต่อเนื่องและเชื่อมกัน ไม่ใช่ขั้นตอนเส้นตรง

**PCC หยิบใช้:** กำกับความเสี่ยงตั้งแต่ทดลองจนใช้งานจริง

### ISO/IEC 42001:2023 [S5]

มาตรฐานสากล • ระบบบริหารจัดการ AI ขององค์กร

PLAN (วางแผน) → DO (ดำเนินการ) → CHECK (ตรวจทบทวน) → ACT (ปรับปรุง)

↺ นโยบาย • เจ้าภาพ • หลักฐาน • ปรับปรุงต่อเนื่อง

นำแนวคิดมาใช้ ≠ ได้รับการรับรองมาตรฐาน

**PCC หยิบใช้:** ระบบบริหารที่ทำต่อได้ ไม่พึ่งคนเก่งคนเดียว

### OECD AI Principles [S6]

หลักการระหว่างประเทศ • แสดง 5 หลักด้านคุณค่า

1. ประโยชน์ทั่วถึง การพัฒนายั่งยืน และความเป็นอยู่ที่ดี
2. สิทธิมนุษยชน ประชาธิปไตย ความเป็นธรรม และความเป็นส่วนตัว
3. โปร่งใสและอธิบายได้
4. เชื่อถือได้ มั่นคงปลอดภัย และไม่ก่ออันตราย
5. มีผู้รับผิดชอบและตรวจสอบได้

**PCC หยิบใช้:** คุณค่าทางธุรกิจต้องไม่แลกกับความไม่รับผิดชอบ

### สังเคราะห์เป็น PCC Framework

ผลลัพธ์ + คน ← งานร่วมกับ AI ← ด่านหลักฐาน ← ข้อมูล + แพลตฟอร์ม ← การกำกับดูแล

โครง PCC เป็นข้อเสนอที่สังเคราะห์ใหม่ ไม่ใช่โมเดลที่หน่วยงานทั้งหกร่วมรับรอง • ดูภาพ 02

ภาพย่อเรียบเรียงใหม่เพื่อการสอน • แหล่งต้นฉบับ [S1–S6] อยู่ในคู่มือ • NIST 1.0 อยู่ระหว่างปรับปรุง

## บอร์ด 2 — PCC AI Transformation Framework

TEACHING BOARD 02

Target Model (กรอบเป้าหมาย) • ใช้ได้ทุกหน่วยงาน • สอนเป็นชั้น พัฒนาเป็นขั้น และเรียนรู้กลับเข้าระบบ

### 6 ชั้นของกรอบ

| ชั้น | สาระหลัก | รายละเอียด |
|---|---|---|
| 01 ผลลัพธ์และคน; Business Impact + Capability | ธุรกิจดีขึ้นจริง + ทีมทำต่อเองได้ | ตามด้วยการใช้จริงอย่างต่อเนื่อง → การใช้ซ้ำและขยายผล • แยกผลงาน / ผลลัพธ์ / ผลกระทบ |
| 02 วิธีทำงานร่วมกัน; Human–AI Workflow | คนเป็นเจ้าของปัญหา • AI ช่วยงาน • คนรับผิดชอบการตัดสินใจ | Assistant (ช่วยงาน) → Copilot (ทำงานร่วมกัน) → Agent (ทำหลายขั้นในขอบเขตที่อนุญาต) |
| 03 ด่านหลักฐาน; Evidence-based Gates | โจทย์ → G1 ต้นแบบ → G2 ทดลองจริง → G3 พัฒนาระบบจริง | → G4 เปิดใช้ → G5 ขยายผล • ทุกด่านบอกหลักฐาน เจ้าภาพ และทรัพยากรที่จะใช้ต่อ |
| 04 ข้อมูลและความรู้; Data & Knowledge | ตรวจข้อมูลก่อนวิเคราะห์ • ตรวจที่มาได้ • ใช้ข้อมูลเท่าที่จำเป็น | ข้อมูลธุรกรรม / นิยามและสูตร / วิธีทำงาน / ข้อยกเว้น / ชุดทดสอบ / บทเรียนที่ใช้ซ้ำได้ |
| 05 เครื่องมือและระบบกลาง; Progressive Platform | เครื่องมือที่อนุมัติ → เชื่อมงาน → บริการกลาง → เชื่อมหลายระบบ | ChatGPT / Claude เป็นตัวเลือก ไม่ใช่แพลตฟอร์มครบชุด • เริ่มเล็ก แล้วใช้สิ่งที่พิสูจน์แล้วซ้ำ |
| 06 เจ้าภาพและการกำกับ; Governance & Trust | เจ้าของธุรกิจ + IT/Data + ผู้ดูแลความเสี่ยง + คณะพิจารณา | สิทธิ์ข้อมูล / คนอนุมัติ / บันทึกการทำงาน / เฝ้าระวัง / หยุดและย้อนกลับ • ครอบคลุมทุกชั้น |

### สองเส้นทาง • ระบบพัฒนาเดียวกัน

- 7 ทีมที่ผ่าน → เดินหน้าตามเดิม
- 17 ทีม → พัฒนาแล้วขอเพิ่มเข้ามา; ไม่ต้องแทนที่ 7 ทีมเดิม

### เส้นทางพัฒนา 17 ทีม

เกือบ 3 เดือน • กรอบเสนอประมาณ 12 สัปดาห์

- 01 คะแนนเดิม → วินิจฉัยช่องว่าง
- 02 ปรับโจทย์ → ตรวจข้อมูล
- 03 Mentor + ผู้เชี่ยวชาญช่วยพัฒนา
- 04 ทดลอง → เก็บหลักฐาน
- 05 Final Challenge (ทบทวนรอบสุดท้าย)

↩ กลับเข้าด่านหลักตามความพร้อม
**พัฒนาต่อ / ทดลองจริง / เตรียมระบบจริง**

### บทบาท

- **COO:** เปิดโครงการ / กลางทาง / รอบสุดท้าย
- **Earth:** ประสาน + วิเคราะห์ + ติดตาม
- **Mentor:** ประจำด้าน + ผู้เชี่ยวชาญเสริม

### แถบล่าง

**วงจรเรียนรู้:** ทดลอง → วัดผล → สอนกลับ → เก็บเป็นความรู้ → ใช้ซ้ำ

**ไม่บังคับทุกงานให้เป็น Agent หรือขึ้นระบบจริงใน 3 เดือน**

กรอบสังเคราะห์ PCC [S1–S6] • เป็นข้อเสนอ ไม่ใช่สถานะระบบหรืออำนาจที่ได้รับอนุมัติแล้ว

## บอร์ด 3 — ตัวอย่างเต็มเส้นทาง • เครดิตและการติดตามลูกหนี้

TEACHING BOARD 03

กรณีสาธิตสำหรับโค้ชทีม • ไม่ใช่การวินิจฉัยโครงการเดิม และยังไม่มีผลทดลองของ PCC

### เริ่มจากสาเหตุจ่ายช้า ไม่เริ่มจาก “ต้องมี AI”

| สาเหตุ | สิ่งที่ต้องทำ |
|---|---|
| เอกสารไม่ครบ | แก้ส่งมอบ / วางบิล / ยืนยันรับ |
| ข้อพิพาท / เงินประกัน | แยกเหตุผลและผู้รับผิดชอบ |
| ตามงานไม่ทัน | จัดคิวและกำหนดงานถัดไป |
| ความเสี่ยงลูกค้า | ทบทวนเงื่อนไขโดยผู้มีอำนาจ |

### 1 • ข้อมูลก่อน AI

- ลูกค้า / ใบแจ้งหนี้ / วันครบกำหนด / การรับชำระ
- ใบลดหนี้ / ชำระบางส่วน / ข้อพิพาท / การติดตาม
- **QC:** รหัสเชื่อมกัน • ไม่ซ้ำ; กระทบยอดกับบัญชี • ใช้วันตัดยอดเดียวกัน
- ทดลองกับข้อมูลที่ได้รับอนุญาต; เริ่มจากกลุ่มลูกค้าที่กำหนดขอบเขตชัด

### 2 • เลือกเทคโนโลยีให้ตรงงาน

| เทคโนโลยี | บทบาท |
|---|---|
| กฎ + ระบบเดิม | คำนวณวันค้าง ยอดค้าง และคิวงาน; เป็นฐานเปรียบเทียบก่อนเพิ่ม AI |
| AI ภาษา | สรุปประวัติลูกหนี้ / ร่างข้อความ; อ้างอิงเอกสาร ไม่สร้างยอดเงินเอง |
| แบบจำลองสถิติ | ทดลองเตือนล่วงหน้าเมื่อข้อมูลพอ; ต้องดีกว่ากฎง่าย ๆ บนข้อมูลทดสอบ |

เริ่มช่วยงาน → ทำงานร่วมกับคน • ยังไม่ให้ AI เปลี่ยนวงเงินหรือส่งข้อความเอง

### 3 • คนกับ AI ในงานจริง

ระบบดึงข้อมูล + ตรวจยอด → AI สรุปเหตุ + เสนอคิว → คนตรวจ + ตัดสินใจ → ทำงาน + บันทึกผล

**คนอนุมัติ:** การสื่อสารลูกค้า / เปลี่ยนเงื่อนไขเครดิต / การดำเนินการทางกฎหมาย ตามอำนาจเดิม

- **ผลระยะสั้น** — เวลาสุทธิ • งานตกหล่น • เอกสารครบ
- **ผลด้านเงิน** — เก็บเงินตรงเวลา • ยอดค้างตามรุ่น
- **ความสามารถทีม** — ตรวจคำตอบและทำซ้ำเองได้
- **ข้อควรระวัง** — ก่อน–หลังอย่างเดียวไม่พิสูจน์เหตุ

### เส้นทางตามด่าน

| ช่วง | สิ่งที่ทำ | ด่าน |
|---|---|---|
| โจทย์ + ข้อมูล | แยกสาเหตุค้าง; ตั้งค่าฐานและผู้ใช้ | G1 → อนุมัติทำต้นแบบ |
| ต้นแบบ | กฎพื้นฐาน + AI สรุป; ทดสอบแบบไม่ส่งจริง | G2 → อนุมัติทดลองจริง |
| ทดลองหน้างาน | ขอบเขตเล็ก / คนตรวจ; เทียบวิธีเดิมและบันทึกผล | G3 → อนุมัติพัฒนาระบบจริง |
| เตรียมระบบจริง | IT/Data รับช่วงเทคนิค; เจ้าของธุรกิจยังรับผลลัพธ์ | G4 → อนุมัติเปิดใช้งาน |
| ใช้งานจริง | มีผู้ดูแล / เฝ้าระวัง; หยุดและย้อนกลับได้ | G5 → อนุมัติขยายผล |
| ใช้ซ้ำ / ขยายผล | นำส่วนที่ใช้ร่วมกันได้; ไปใช้กับหน่วยงานถัดไป | หลังพิสูจน์ความคุ้มค่า |

### เกณฑ์และหมายเหตุ

**เกณฑ์พิสูจน์:** เทียบงานและช่วงเวลาที่ใกล้กัน รวมเวลาแก้คำตอบผิดและต้นทุนระบบ • DSO / หนี้เสียต้องดูตามรอบที่เหมาะสม

**หมายเหตุ:** เน้นระบบภายในก่อน • อนาคตอาจร่วมกับธนาคาร / Fintech / ผู้ให้เทคโนโลยีเมื่อความพร้อมเหมาะสม

ตัวอย่างออกแบบโดยสังเคราะห์ • ยังไม่กำหนดเป้าลดหนี้เสียหรือผลตอบแทน • รายละเอียดนิยามและการทดสอบอยู่ในคู่มือ

## บอร์ด 4 — COO Coaching & Gate Board

TEACHING BOARD 04

สอนให้คิด → ทดสอบสมมติฐาน → พิสูจน์คุณค่า → ตัดสินใจโดยมีหลักฐาน

### คำถามโค้ช 4 ขั้น

| ขั้น | คำถาม |
|---|---|
| 1 • สอน | งานเดิมทำอย่างไร?; ใครเดือดร้อน และอยากให้ดีขึ้นตรงไหน? |
| 2 • ท้าทาย | ไม่ใช้ AI แก้ได้ไหม?; หลักฐานอะไรจะบอกว่าเราคิดผิด? |
| 3 • พิสูจน์ | ดีกว่าวิธีเดิมจริงเท่าไร?; ทีมทำเองได้ และผู้ใช้ยืนยันหรือยัง? |
| 4 • จับสัญญาณเตือน | มีเดโมแต่ไม่มีค่าฐาน?; AI ผิดแล้วใครหยุดหรือย้อนกลับ? |

### ตารางด่าน

| ด่าน / สิ่งที่จะอนุมัติ | คำถามหลักของ COO | หลักฐานขั้นต่ำก่อนเดินต่อ |
|---|---|---|
| G1 ทดลองต้นแบบ | โจทย์คุ้มแก้ และข้อมูลใช้ได้หรือไม่? | เจ้าของปัญหา + ค่าฐาน + สิทธิ์ข้อมูล + วิธีไม่ใช้ AI |
| G2 ทดลองหน้างาน | ต้นแบบปลอดภัยพอให้ผู้ใช้ลองหรือยัง? | ผลทดสอบ + คนตรวจ + ขอบเขตทดลอง + เงื่อนไขหยุด |
| G3 พัฒนาระบบจริง | ผู้ใช้และผลธุรกิจรองรับการลงทุนหรือไม่? | ก่อน–หลังและตัวเทียบ + ผู้ใช้ยืนยัน + ทีมทำต่อได้ + IT รับได้ |
| G4 เปิดใช้งานจริง | ใครดูแล และเมื่อผิดพลาดจะทำอย่างไร? | ผลรับรองระบบ + สิทธิ์/ความเสี่ยง + ผู้ดูแล + แผนย้อนกลับ |
| G5 ขยายผล | ใช้ซ้ำคุ้มกว่า และหน่วยงานใหม่พร้อมหรือไม่? | ผลต่อเนื่อง + ต้นทุนขยาย + เจ้าภาพปลายทาง + ทดสอบบริบทใหม่ |

### ชุดหลักฐานเดียวกัน

- โจทย์และค่าฐาน • ผลทดลอง • เสียงผู้ใช้
- เดโมและผลทดสอบ • ทักษะทีม
- ข้อมูล / เทคโนโลยี / ความเสี่ยงตามด่าน

หลักฐานที่ขาด = ยังไม่ยืนยัน ไม่ใช่ศูนย์หรือผ่าน

### แบ่งหน้าที่ชัด

- **COO + คณะพิจารณา:** ตัดสินตามอำนาจ
- **Earth:** ตรวจความครบ ประสาน ติดตาม
- **Mentor:** ช่วยพัฒนา • **ทีม:** พิสูจน์และทำต่อ

Earth ไม่ใช่ผู้อนุมัติผ่านด่านหรือผู้รับรองผลธุรกิจ

### ผลตัดสินต้องบอกทางไปต่อ

- เดินต่อ / ปรับแล้วกลับมา / พัก / หยุด
- ระบุขั้นถัดไป เจ้าภาพ ทรัพยากร และวันทบทวน
- **ผ่านกลับมาได้ โดยไม่แทนที่ 7 ทีม**

ความปลอดภัยและสิทธิ์ข้อมูลไม่ถูกชดเชยด้วยคะแนนสูง

### แถบล่าง

**เกณฑ์กลาง + เกณฑ์เฉพาะด้าน** • เทียบกับเกณฑ์เดิมก่อนปรับ • ยังไม่ล็อกน้ำหนักคะแนน

ผลธุรกิจ + ความสามารถทีม → การใช้จริง → ขยายผล

แบบโค้ชและด่าน PCC ที่เสนอ • ไม่ใช่ข้อกำหนดมาตรฐานต้นฉบับ • คณะและอำนาจอนุมัติต้องยืนยันก่อนใช้จริง
