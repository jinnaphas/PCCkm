# คู่มือการใช้งาน Paradigm Library และการซิงก์กับ OneDrive

ฉบับ 21 ตุลาคม 2569 — คู่มือการใช้เว็บ การเพิ่มเอกสารทั้งจากหน้าเว็บและจากแชท Claude และการทำให้ข้อมูลบนเว็บตรงกับ OneDrive ส่วนคู่มือฉบับเต็มของฐานความรู้ Business Management (ฝั่ง OneDrive และคำสั่งของเครื่องมือ) อยู่ที่ git: `docs/BM_Folder_User_Guide_20261012.md` (และฉบับ HTML `docs/BM_Folder_User_Guide_20261012.html`) และที่ OneDrive: `Business Management/Manual/` ถ้ามีข้อใดไม่ตรงกัน ให้ยึดฉบับเต็มนั้น

## 1. โครงสร้างหมวดหมู่

เว็บแบ่งเป็น 4 กลุ่ม แต่ละกลุ่มมี 2 ส่วน:

- **Paradigm** — เอกสารกรอบแนวคิด แผนผัง โมเดล ใส่ไฟล์หรือลิงก์ได้เลย **ไม่ต้องมีไฟล์ .md และไม่ต้องมีรหัสเอกสาร**
- **Knowledge Management** — ฐานความรู้ที่ใช้กับ LLM **ต้องมีไฟล์ .md และ Tag รหัสเอกสาร** `BM-xxx-nnn` (ดูข้อ 5)

เมนูซ้ายแสดงชื่อภาษาอังกฤษของหมวด กดลูกศรเพื่อขยายหรือหุบหมวดย่อย และชี้เมาส์ที่ชื่อเพื่อดูชื่อเต็ม

## 2. การค้นหาและเปิดดูเอกสาร

- ใช้ช่อง **ค้นหา** ด้านบน (กด `/` เพื่อโฟกัส) ค้นจาก **ชื่อเอกสาร, Tag, คำอธิบาย และชื่อหมวด** ทันทีที่พิมพ์ หรือเลือกหมวดหมู่แล้วกรองด้วย Tag
- ใส่รหัสเอกสาร เช่น `BM-STR-004` เพื่อหาเอกสารของฐานความรู้ตรงตัว
- หน้าเอกสารแสดงตัวอย่าง (PDF, รูปภาพ, วิดีโอ, Markdown) ปุ่ม **ดาวน์โหลด** และ **ประวัติเวอร์ชัน** ย้อนดูไฟล์เก่าได้
- เอกสารใน Knowledge Management มีแถบ **Markdown for LLM**: **ดู .md**, **คัดลอกข้อความ** (นำไปวางในแชทของ LLM ได้ทันที) และ **ดาวน์โหลด .md** ถ้าเห็นแถบเตือนสีเหลือง แปลว่าเอกสารนั้นยังไม่มีไฟล์ .md

## 3. ก่อนเริ่มเพิ่มเอกสารบนเว็บ (ทำครั้งเดียว)

ต้องมี GitHub Token ที่เขียน repo นี้ได้ (ดูอย่างเดียวไม่ต้องใช้):

- เข้า GitHub › Settings › Developer settings › **Fine-grained personal access tokens** › Generate new token
- Repository access: เลือกเฉพาะ repo PCCkm
- Permissions: **Contents → Read and write** (แค่นี้พอ)
- กดปุ่ม **เข้าสู่ระบบ** มุมขวาบน ใส่ชื่อที่แสดงและ Token ระบบจำไว้ในเบราว์เซอร์เครื่องนั้น ไม่ควรแชร์ Token ให้ผู้อื่น และออกจากระบบเมื่อใช้เครื่องร่วมกัน

## 4. เพิ่มเอกสารบนเว็บ — แบบ Paradigm (ไม่ต้องมี .md)

1. กดปุ่ม **+ เพิ่มเอกสาร** (มุมขวาบน)
2. **ชื่อเอกสาร** — ชื่อที่ใช้ค้นหาและแสดงผล
3. **คำอธิบาย** — สรุปสั้นๆ ว่าเอกสารนี้คืออะไร ใช้เมื่อไหร่
4. **หมวดหมู่** — เลือกแท็บ Paradigm ของกลุ่มที่ต้องการ เช่น กลุ่ม 1 Strategy › Paradigm (เลือกหมวดย่อยของ Paradigm ได้ เช่น Intellectual Capital › Human Capital)
5. **Tag** — คั่นด้วยเครื่องหมายจุลภาค ไม่บังคับ แต่ช่วยการค้นหา
6. **เพิ่มไฟล์แนบ** — เลือกได้หลายไฟล์พร้อมกัน และ/หรือกด **+ เพิ่มลิงก์ภายนอก** (YouTube, Google Drive ฯลฯ) ต้องมีอย่างน้อย 1 อย่าง
7. กด **เพิ่มเอกสาร** — ระบบอัพโหลดไฟล์และเก็บเข้าคลังทันที เปิดหน้าเอกสารให้ดู

ไฟล์ไม่ควรเกิน ~50 MB ต่อไฟล์ วิดีโอใหญ่ให้ใช้ลิงก์ภายนอกแทน

หลังเพิ่ม: โฟลเดอร์ `Paradigm` บน OneDrive เป็นสำเนาที่ **ไม่ซิงก์ให้เอง** ถ้าต้องการให้มีไฟล์นั้นด้วย ให้นำไฟล์ไปวางใน `Paradigm/<กลุ่ม>/` และเพิ่มแถวใน `Paradigm/00_INDEX.csv` หรือสั่ง Claude ให้ทำ (ข้อ 7)

## 5. เพิ่มเอกสารบนเว็บ — แบบ Knowledge Management (ต้องมี .md และรหัส)

เตรียมก่อนเปิดฟอร์ม: ไฟล์ต้นฉบับชื่อ `BM-xxx-nnn_ชื่อไฟล์` และไฟล์ .md ที่แปลงแล้วชื่อ `BM-xxx-nnn_ชื่อ.md` (รหัสหมวดและลำดับดูในสารบัญ `00_INDEX.md`)

1. กด **+ เพิ่มเอกสาร** แล้วเลือกหมวดย่อยใต้ **Knowledge Management** ที่ตรงกับเรื่อง
2. เมื่อเลือกหมวดแล้ว จะมีช่อง **ไฟล์ Markdown (.md) สำหรับ LLM** ขึ้นมา — บังคับ
3. **ชื่อเอกสาร** — ใช้ชื่อเดียวกับ `title` ใน .md และชื่อในสารบัญ
4. **Tag** — ต้องมีรหัสเอกสาร เช่น `BM-STR-005` (ใส่ Tag อื่นเพิ่มได้)
5. แนบไฟล์ต้นฉบับใน "เพิ่มไฟล์แนบ" และไฟล์ .md ในช่อง .md แล้วกดบันทึก
6. ถ้าขาด .md หรือขาดรหัส ระบบจะไม่ให้บันทึกและแจ้งสาเหตุ
7. **นำกลับมาลง OneDrive ให้ตรงกันด้วย** (ข้อ 8): วางต้นฉบับใน `Business Management From GG Drive/<โฟลเดอร์หมวด>/` และ .md ใน `knowledge_md/<โฟลเดอร์หมวด>/` ใช้ชื่อไฟล์เดียวกับที่อัพโหลด แล้วเพิ่มรายการใน 00_INDEX.md และ 00_INDEX.csv

## 6. อัพเดต ลบ และเพิ่มหมวดหมู่

- **อัพเดตเอกสารเดิม:** เปิดหน้าเอกสาร กด **อัพเดตเวอร์ชัน / แก้ไข** เลือกไฟล์ใหม่ใส่บันทึกว่าแก้อะไร ระบบเพิ่มเลขเวอร์ชันให้เองและเก็บไฟล์เก่าไว้ย้อนดูได้ สำหรับ Knowledge Management ต้องแนบ .md ฉบับใหม่ด้วย และแก้ฝั่ง OneDrive ให้ตรงกัน
- **ลบเอกสาร:** ปุ่ม **ลบ** เอาออกจากหน้าเว็บเท่านั้น ไฟล์ยังอยู่ใน git history กู้คืนได้ ต้องแก้ OneDrive และสารบัญให้ตรงกันด้วย
- **เพิ่มหมวดหมู่:** ปุ่ม **+ เพิ่มหมวดหมู่** ใต้เมนูซ้าย เลือกหมวดแม่ได้ทุกระดับ แต่ยังแก้ชื่อหรือลบหมวดจากหน้าเว็บไม่ได้ (ต้องแก้ไฟล์ข้อมูลผ่านผู้ดูแล) และถ้าเป็นหมวดใหม่ของฐานความรู้ ต้องเพิ่มในตารางจับคู่ของเครื่องมือและสารบัญด้วย

## 7. เพิ่มเอกสารผ่านแชท Claude

ใช้ได้เมื่อเปิด Claude (Cowork หรือ Claude Code) ในโฟลเดอร์ที่มี repo PCCkm และโฟลเดอร์ OneDrive Business Management อยู่ในเครื่องเดียวกัน ไม่ต้องกรอกฟอร์มบนเว็บและไม่ต้องใช้ GitHub Token ของคุณ Claude แก้ไฟล์ในเครื่องให้

**Claude ทำอะไรให้**
- อ่านไฟล์ที่คุณระบุ แล้วเสนอ ชื่อเอกสาร คำอธิบาย Tag และหมวด ให้คุณยืนยัน
- เพิ่มไฟล์ลงโฟลเดอร์ assets และเพิ่มรายการใน data/library.json (เลขเวอร์ชันและประวัติให้ครบ)
- เก็บสำเนาใน OneDrive และอัปเดตสารบัญ: Paradigm ลงโฟลเดอร์ `Paradigm/<กลุ่ม>/` และ Paradigm/00_INDEX.csv ส่วน Knowledge Management ตั้งรหัส BM แล้วย้ายต้นฉบับ แปลง .md อัปเดต 00_INDEX.md/.csv และรัน tools/check_sync.pl
- commit และ push เมื่อคุณสั่ง (ไม่ push เอง) แล้วเปิด Pull Request ให้เมื่อต้องการขึ้นหน้าเว็บจริง

**ข้อความสั่งตัวอย่าง — Paradigm**
> เพิ่มไฟล์ C:\Users\<ชื่อ>\Downloads\ชื่อไฟล์.pdf ใน Paradigm หมวด Strategy ตั้งชื่อเอกสารว่า "..." (ถ้าไม่ระบุ ให้ตั้งชื่อจากเนื้อหา) เก็บสำเนาใน OneDrive โฟลเดอร์ Paradigm และอัปเดตสารบัญ

**ข้อความสั่งตัวอย่าง — Knowledge Management**
> ไฟล์ C:\Users\<ชื่อ>\Downloads\ชื่อไฟล์.pdf เป็นเอกสารฐานความรู้ หมวด <เช่น Digital & AI Transformation> ช่วยเสนอรหัส BM ให้ approve ก่อน แล้วย้ายเข้า Business Management From GG Drive แปลงเป็น .md ใน knowledge_md อัปเดต 00_INDEX.md และ 00_INDEX.csv นำขึ้นเว็บ และรัน check_sync

**ต่อท้ายเมื่อพร้อมเผยแพร่**
> commit และ push ขึ้น branch test แล้วเปิด PR เข้า main

**ข้อจำกัดที่ควรรู้**
- **PDF แบบรูปภาพ/สแกน** (เช่นสไลด์ที่ส่งออกเป็นรูป) ไม่มีตัวอักษรให้ดึง Claude อ่านจากรูปและเขียนคำอธิบายให้ได้ แต่ไฟล์ .md ของ Knowledge Management จะเป็นการถอดความที่ต้องตรวจทานก่อนใช้งานจริง
- **สิทธิ์ของระบบ:** Claude อาจถูกขออนุญาตหรือถูกปฏิเสธเมื่อคัดลอกไฟล์ภายในจาก OneDrive เข้า repo หรือเมื่อ merge Pull Request ให้คุณอนุญาตตามที่ระบบถาม หรือรันคำสั่งที่ Claude ให้เอง และให้ผู้ดูแลกด merge
- **ขึ้นเว็บจริงเมื่อไหร่:** Claude แก้ไฟล์ในเครื่อง เว็บบน GitHub ยังไม่เปลี่ยนจนกว่าจะ push แล้ว merge เข้า main (Pages จะ deploy เอง ใช้เวลาประมาณ 1–2 นาที)
- **repo เป็น Public:** ไฟล์ที่ push ขึ้นไปทุกคนเปิดอ่านได้ Claude จะถามยืนยันก่อน push เอกสารภายใน
- ไฟล์ใหญ่เกิน ~50 MB ควรใช้ลิงก์ภายนอก

## 8. ให้ข้อมูลบนเว็บกับ OneDrive ตรงกันเสมอ

ข้อมูลของฐานความรู้อยู่ 2 ที่ และต้องตรงกัน: **OneDrive** (ต้นฉบับ, ไฟล์ .md, สารบัญ 00_INDEX) และ **เว็บนี้** เอกสารแต่ละเรื่องใน Knowledge Management ต้องมีครบ 4 อย่าง คือ ต้นฉบับ, ไฟล์ .md, รายการในสารบัญ และรายการบนเว็บ

- **เพิ่มบน OneDrive ก่อน:** วางต้นฉบับชื่อ `BM-xxx-nnn_...` ให้ Claude แปลง .md และอัปเดตสารบัญ แล้วผู้ดูแลรัน `tools/sync_from_onedrive.pl` เพื่อนำขึ้นเว็บ (หรือสั่ง Claude ตามข้อ 7)
- **เพิ่มบนเว็บก่อน:** เพิ่มตามข้อ 5 แล้วนำไฟล์ต้นฉบับและ .md ไปวางใน OneDrive ด้วยชื่อเดียวกัน พร้อมเพิ่มรายการในสารบัญ
- **ตรวจว่าตรงกัน:** ผู้ดูแลรัน `tools/check_sync.pl` หลังเพิ่มหรือแก้เอกสารทุกครั้ง เครื่องมือจะรายงานเอกสารที่ขาดหรือไฟล์ที่ต่างกัน
- **Paradigm:** ไม่มีเครื่องมือตรวจ — โฟลเดอร์ `Paradigm` บน OneDrive เป็นสำเนาที่อัปเดตเมื่อมีการเพิ่มหรือแก้ (ให้ Claude ทำให้ได้)

ขั้นตอนละเอียด คำสั่งที่ใช้ และกรณีพิเศษ ดูในคู่มือฉบับเต็มบน OneDrive

## 9. แก้ปัญหาเบื้องต้น

- **"Token ไม่ถูกต้อง หรือหมดอายุ"** — สร้าง Token ใหม่ตามข้อ 3 แล้วเข้าสู่ระบบอีกครั้ง
- **GitHub API error (403) หรือ (404) ตอนบันทึก** — Token ไม่มีสิทธิ์เขียน repo นี้ ตรวจว่าเลือก repo PCCkm และตั้ง Contents เป็น Read and write
- **GitHub API error (409) หรือ (422)** — มีคนแก้พร้อมกัน หรือมีไฟล์ชื่อเดียวกันในเวอร์ชันเดียวกันอยู่แล้ว ให้รีเฟรชหน้า ตรวจว่าเอกสารถูกบันทึกไปหรือยัง แล้วลองใหม่ (ถ้าซ้ำ ให้เปลี่ยนชื่อไฟล์)
- **บันทึกเอกสารใน Knowledge Management ไม่ได้** — ตรวจว่าแนบไฟล์ .md (นามสกุล .md หรือ .markdown) และใส่ Tag รหัส `BM-xxx-nnn` ในรูปแบบที่ถูกต้องแล้ว
- **เพิ่มเอกสารแล้วเปิดไฟล์ไม่ได้ (404) ชั่วคราว** — ไฟล์มาจากเว็บที่ deploy รอบละประมาณ 1 นาที รอสักครู่แล้วรีเฟรช
- **เห็นแถบเตือนสีเหลืองในหน้าเอกสาร** — เอกสารใน Knowledge Management นั้นยังไม่มีไฟล์ .md ให้กด อัพเดตเวอร์ชัน / แก้ไข แล้วแนบ .md

## 10. ข้อควรรู้

- ผู้เยี่ยมชมที่ไม่ได้เข้าสู่ระบบเห็นข้อมูลตามรอบ deploy (ช้ากว่าจริงประมาณ 1 นาที) ส่วนผู้ที่เข้าสู่ระบบเห็นข้อมูลสด
- เอกสารส่วนใหญ่ในฐานความรู้เป็น "ข้อเสนอ" ที่ยังไม่ใช่เรื่องที่อนุมัติ ให้ตรวจ "สถานะ" และ "ความน่าเชื่อถือ" ก่อนนำไปอ้างอิง
- repo เป็น Public: ทุกไฟล์ที่เพิ่มบนเว็บ ทุกคนเปิดอ่านได้ ก่อนนำเอกสารภายในขึ้นเว็บ ให้ตกลงเรื่องสิทธิ์การเผยแพร่
