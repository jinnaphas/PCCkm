1. ภาพรวม: ข้อมูลอยู่ 2 ที่ และต้องตรงกันเสมอ

  • OneDrive (Business Management - Documents / Business Management): เก็บไฟล์ต้นฉบับ, ไฟล์ .md ที่แปลงแล้ว (knowledge_md/) และสารบัญ (00_INDEX.md, 00_INDEX.csv) — ต้นฉบับคือแหล่งอ้างอิงสุดท้าย ถ้าเนื้อหาใน .md ขัดกับต้นฉบับ ให้ยึดต้นฉบับ
  • เว็บ Paradigm Library: ค้นหา เปิดดู และดาวน์โหลดเอกสาร เก็บข้อมูลใน repo PCCkm (data/library.json + โฟลเดอร์ assets/)
  • กุญแจที่ใช้จับคู่ 2 ที่คือรหัสเอกสาร BM-<รหัสหมวด>-<ลำดับ 3 หลัก> เช่น BM-STR-004
  • เอกสาร 1 เรื่องใน Knowledge Management ต้องมีครบ 4 อย่าง จึงถือว่าเสร็จ:

    2. ไฟล์ .md ใน knowledge_md/<โฟลเดอร์หมวด>/
    3. แถวและรายการของเอกสารใน 00_INDEX.csv และ 00_INDEX.md
    4. รายการเอกสารบนเว็บ (หมวดใต้ Knowledge Management) พร้อมไฟล์ต้นฉบับ และไฟล์ .md ที่เป็นปุ่ม "Markdown for LLM"

2. โครงสร้างหมวดบนเว็บ

เว็บแบ่งเป็น 4 กลุ่ม แต่ละกลุ่มมี Paradigm (เอกสารกรอบแนวคิด) และ Knowledge Management (ฐานความรู้ แยกเป็นหัวข้อ) เอกสารที่มีรหัส BM อยู่ใน Knowledge Management ทั้งหมด

รหัสหมวดในสารบัญ → หมวดบนเว็บ (ภายใต้ Knowledge Management):

  • STR → กลุ่ม 1 Strategy & Business Model Development
  • COE → กลุ่ม 2 STEM & DBTP › Center of Excellence (CoE)
  • AI → กลุ่ม 3 Operation Technology › Digital & AI Transformation
  • OPS → กลุ่ม 3 Operation Technology › Operations Excellence & Factory 4.0
  • IC, HC, INF, DPC, REL, CUS → กลุ่ม 4 Business Management & Corporate Support › Intellectual Capital (และหมวดย่อย Human / Information / Digital Process / Relationship / Customer Capital ตามลำดับ)
  • REV, BG, DS → กลุ่ม 4 › 6 Revenue Stream Types / Business Generation / Demand Satisfaction
  • ESG, FIN, POL, PRJ, MTG, REF → กลุ่ม 4 › ESG & Sustainability / Finance & Budget / Policy, Risk & Compliance / Projects, KPI & Performance / Meetings & Decisions / External References & Standards

ตารางเต็มอยู่ใน 00_INDEX.md หัวข้อ "การจัดหมวดบนเว็บ Paradigm Library" ถ้าเพิ่มหมวดใหม่ ต้องแก้ทั้งตารางนั้นและรายการหมวดในเครื่องมือตรวจ (ข้อ 7)

3. กติกาที่ต้องทำเสมอ

  • ตั้งชื่อไฟล์ขึ้นต้นด้วยรหัสเอกสาร ทั้งต้นฉบับและ .md เช่น BM-STR-004_ชื่อไฟล์เดิม.pdf และ BM-STR-004_bamboo-business-intelligence.md — ชื่อไฟล์ที่อัพโหลดบนเว็บต้องเหมือนใน OneDrive ทุกตัวอักษร ไม่เช่นนั้นเครื่องมือตรวจจะถือว่าคนละไฟล์
  • ทุกเอกสารใน Knowledge Management ต้องมีไฟล์ .md — เว็บจะไม่ให้บันทึกถ้าไม่แนบ
  • ต้องมี Tag รหัสเอกสาร (เช่น BM-STR-004) ในช่อง Tag บนเว็บ — เว็บจะไม่ให้บันทึกถ้าไม่ใส่ รหัสนี้คือกุญแจจับคู่กับสารบัญ
  • ชื่อเอกสาร (title) ต้องเหมือนกัน 3 ที่: หัว title ใน .md, คอลัมน์ "ชื่อเอกสาร" ใน 00_INDEX.csv และชื่อเอกสารบนเว็บ
  • ห้ามแก้เนื้อหาหรือเปลี่ยนชื่อไฟล์ต้นฉบับ และห้ามย้ายข้ามหมวดโดยไม่อัปเดตสารบัญ .md และเว็บ
  • ห้ามแก้ไฟล์ .md ด้วยมือโดยไม่อัปเดตสารบัญทั้ง 2 ไฟล์ และไม่ลืมแก้สำเนาบนเว็บ
  • ห้ามอ้างเอกสารสถานะ "ข้อเสนอ" ว่าเป็นนโยบายหรือเรื่องที่อนุมัติแล้ว
  • เอกสารที่ยกเลิก: ไม่ลบไฟล์ ให้เปลี่ยน status เป็น "ยกเลิก / แทนที่ด้วย BM-…" ทั้งใน .md และสารบัญ

4. ทางที่ 1 — ใส่ไฟล์ไว้บน OneDrive ก่อน

  1. วางต้นฉบับ ในโฟลเดอร์หมวดที่ตรงกันใน Business Management From GG Drive/ ตั้งชื่อ BM-xxx-nnn_ชื่อไฟล์เดิม (ลำดับ 3 หลักต่อจากเลขล่าสุดของหมวด) เอกสารที่มีหลายฟอร์แมต (เช่น docx + pdf) ใช้รหัสเดียวกัน
  2. สั่ง Claude (ข้อ 8) ให้แปลงเป็น .md ใน knowledge_md/<โฟลเดอร์หมวด>/ เสนอหมวดและรหัส และเพิ่มรายการใน 00_INDEX.md กับแถวใน 00_INDEX.csv
  3. เจ้าของข้อมูลตรวจ สถานะ ความน่าเชื่อถือ access_level และจุด [อ่านไม่ชัด] กับต้นฉบับ (ถ้า .md ถูกสกัดข้อความอัตโนมัติ ให้ระบุไว้ใน conversion และตรวจก่อนใช้งานจริง)
  4. นำขึ้นเว็บ (ผู้ดูแลที่มี repo PCCkm ในเครื่อง รันใน Git Bash ที่โฟลเดอร์ repo):
    • ดูแผนก่อน: perl tools/sync_from_onedrive.pl "<โฟลเดอร์ OneDrive>"
    • เขียนจริง: เติม --apply ท้ายคำสั่ง — สคริปต์จะคัดลอกต้นฉบับ + .md ไปที่ assets/<หมวด>/<bm-xxx-nnn>/ และเพิ่มรายการท้าย data/library.json (หมวดตามตารางข้อ 2, ชื่อและ Tag จากหัว .md)
  5. ตรวจว่าตรงกัน ด้วย perl tools/check_sync.pl "<โฟลเดอร์ OneDrive>" (ข้อ 7) แล้วจึง commit และ push (ถ้าตั้งใจเผยแพร่)

สคริปต์นี้เพิ่มเฉพาะ เอกสารใหม่ ที่ยังไม่มีบนเว็บเท่านั้น ถ้าแก้เอกสารเดิม ดูข้อ 6

5. ทางที่ 2 — เพิ่มไฟล์บนเว็บก่อน

  1. เตรียมไฟล์ให้ครบก่อน: ต้นฉบับชื่อ BM-xxx-nnn_... และไฟล์ .md ชื่อ BM-xxx-nnn_...md (หัวไฟล์ .md มี doc_id, title, tags ตามรูปแบบใน 00_INDEX.md)
  2. เปิดเว็บ กด เข้าสู่ระบบ (ชื่อที่แสดง + GitHub Token ที่มีสิทธิ์เขียน repo — ขอจากผู้ดูแล) แล้วกด + เพิ่มเอกสาร
  3. เลือกหมวดย่อยใต้ Knowledge Management ที่ตรงกับตารางข้อ 2 ใส่ชื่อเอกสาร (เหมือน title ใน .md) คำอธิบาย และ Tag รหัสเอกสาร BM-xxx-nnn (เพิ่ม Tag อื่นได้)
  4. แนบไฟล์ต้นฉบับ (ช่อง "เพิ่มไฟล์แนบ") และไฟล์ .md (ช่อง "ไฟล์ Markdown สำหรับ LLM" ที่บังคับ) แล้วกดบันทึก
  5. ต้องนำกลับมาลง OneDrive ให้ตรงกันด้วย (เว็บยังไม่ซิงก์กลับให้เอง):
    • วางต้นฉบับใน Business Management From GG Drive/<โฟลเดอร์หมวด>/ และ .md ใน knowledge_md/<โฟลเดอร์หมวด>/ ใช้ชื่อไฟล์เดียวกับที่อัพโหลด
    • เพิ่มรายการใน 00_INDEX.md และแถวใน 00_INDEX.csv (สั่ง Claude ตามข้อ 8 ได้)
  6. รัน perl tools/check_sync.pl — ต้องขึ้น "OneDrive และเว็บตรงกันทั้งหมด"

5.1 เพิ่มเอกสารบนเว็บ — แบบ Paradigm (ไม่ต้องมี .md และไม่ต้องมีรหัส)

เอกสารในแท็บ Paradigm (กรอบแนวคิด แผนผัง โมเดล) ไม่ต้องแนบไฟล์ .md และไม่ต้องใส่ Tag รหัส BM — บังคับเฉพาะเอกสารใต้ Knowledge Management

  1. เข้าสู่ระบบ (ข้อ 12) แล้วกดปุ่ม + เพิ่มเอกสาร
  2. กรอก ชื่อเอกสาร, คำอธิบาย, เลือก หมวดหมู่ เป็นแท็บ Paradigm ของกลุ่มที่ต้องการ (เลือกหมวดย่อยได้ เช่น Intellectual Capital › Human Capital), ใส่ Tag (ไม่บังคับ)
  3. แนบไฟล์ได้หลายไฟล์ และ/หรือกด + เพิ่มลิงก์ภายนอก ต้องมีอย่างน้อย 1 อย่าง แล้วกด เพิ่มเอกสาร
  4. เก็บสำเนาใน OneDrive โฟลเดอร์ Paradigm/<กลุ่ม>/ และเพิ่มแถวใน Paradigm/00_INDEX.csv (ข้อ 14) — ฝั่ง Paradigm ไม่มีเครื่องมือ check_sync ตรวจให้

6. กรณีพิเศษ

  • ฉบับใหม่ของเอกสารเดิม: ใช้รหัสเดิม แล้วทำให้ครบ ทั้ง 2 ที่: (1) OneDrive — แทนไฟล์ต้นฉบับ แปลง .md ใหม่ แก้ version และ doc_date ในหัว .md และสารบัญ (2) เว็บ — เปิดเอกสาร กด อัพเดตเวอร์ชัน / แก้ไข แนบต้นฉบับและ .md ใหม่ ระบบเก็บไฟล์เวอร์ชันเก่าให้ย้อนดูได้ จากนั้นรัน check_sync ถ้าฝั่งใดยังไม่อัปเดต เครื่องมือจะแจ้งว่าไฟล์ "ต่างกัน"
  • ถ้าต้องเก็บประวัติเป็นอีกเอกสาร: ออกรหัสใหม่ แล้วใส่ related_docs ชี้ฉบับเก่า
  • ไม่มีหมวดที่ตรง: ใช้กติกาแยกหมวดใน 00_INDEX.md เลือกหมวดที่ใกล้ที่สุด หรือเพิ่มหมวดใหม่ทั้งในสารบัญ 2 ไฟล์ บนเว็บ (ปุ่ม + เพิ่มหมวดหมู่) และในตารางจับคู่ของเครื่องมือตรวจ
  • ข้อมูลอ่อนไหว (เงินเดือน สัญญา ชื่อบุคคล): กำหนด access_level ตั้งแต่ตอนแปลง และพิจารณาก่อนนำขึ้นเว็บ — ดูข้อ 9
  • ลบเอกสารบนเว็บ: ปุ่มลบเอาออกจากหน้าเว็บเท่านั้น ไฟล์ยังอยู่ใน git history ถ้าลบแล้ว ต้องแก้ OneDrive และสารบัญให้ตรงกันด้วย

  • ไม่มีแถวใน 00_INDEX.csv / ไม่มีไฟล์ .md / ไม่มีต้นฉบับ / ไม่มีบนเว็บ
  • หมวดบนเว็บไม่ตรงกับรหัสหมวดตามตารางข้อ 2
  • เว็บไม่มีไฟล์ .md (role llm-md) หรือไฟล์ในโฟลเดอร์ assets/ หาย

  • ไฟล์ต้นฉบับมีฝั่งเดียว (ชื่อไม่ตรงกัน)

  • ค้นหา: ช่องค้นหาด้านบน (กด / เพื่อโฟกัส) ค้นจากชื่อเอกสาร Tag คำอธิบาย และหมวดทันทีที่พิมพ์ — ใส่รหัสเอกสาร เช่น BM-STR-004 เพื่อหาเอกสารตรงตัว
  • หมวดหมู่: เมนูซ้ายแสดง 4 กลุ่ม กดลูกศรเพื่อขยาย/หุบหมวดย่อย (ชี้เมาส์ที่ชื่อหมวดเพื่อดูชื่อเต็ม) แล้วกรองด้วย Tag ในหน้าหมวดได้
  • เปิดเอกสาร: หน้าเอกสารมีตัวอย่าง (PDF, รูป, วิดีโอ, Markdown), ปุ่มดาวน์โหลด และประวัติเวอร์ชัน
  • Markdown for LLM: เอกสารใน Knowledge Management มีแถบปุ่ม ดู .md / คัดลอกข้อความ / ดาวน์โหลด .md — กดคัดลอกแล้วนำไปวางในแชทของ LLM ได้ทันที ถ้าเห็นแถบเตือนสีเหลือง แปลว่าเอกสารยังไม่มี .md (ต้องแก้ตามข้อ 3)
  • เพิ่ม/อัพเดต/ลบเอกสาร: ต้องเข้าสู่ระบบด้วย GitHub Token ดูขั้นตอนข้อ 5, 5.1 และ 6 วิดีโอขนาดใหญ่ให้ใช้ลิงก์ภายนอกแทนการอัพโหลด (ไฟล์ไม่ควรเกิน ~50MB)

11. เพิ่มเอกสารผ่านแชท Claude

ใช้ได้เมื่อเปิด Claude (Cowork หรือ Claude Code) ในโฟลเดอร์ที่มี repo PCCkm และโฟลเดอร์ OneDrive Business Management อยู่ในเครื่องเดียวกัน — ไม่ต้องกรอกฟอร์มบนเว็บและไม่ต้องใช้ GitHub Token ของคุณ Claude แก้ไฟล์ในเครื่องให้

Claude ทำอะไรให้

  • อ่านไฟล์ที่คุณระบุ แล้วเสนอชื่อเอกสาร คำอธิบาย Tag และหมวดให้ยืนยัน
  • เพิ่มไฟล์ลง assets/ และเพิ่มรายการใน data/library.json (เลขเวอร์ชันและประวัติครบ)
  • Paradigm: เก็บสำเนาใน Paradigm/<กลุ่ม>/ และเพิ่มแถวใน Paradigm/00_INDEX.csv
  • Knowledge Management: เสนอรหัส BM ให้อนุมัติ ย้ายต้นฉบับเข้า Business Management From GG Drive/ แปลงเป็น .md ใน knowledge_md/ อัปเดต 00_INDEX.md และ 00_INDEX.csv นำขึ้นเว็บ (ใช้ tools/sync_from_onedrive.pl) แล้วรัน tools/check_sync.pl
  • commit และ push เมื่อคุณสั่ง (ไม่ push เอง) และเปิด Pull Request เมื่อต้องการขึ้นหน้าเว็บจริง

  • Claude อาจถูกขออนุญาตหรือถูกปฏิเสธเมื่อคัดลอกไฟล์ภายในจาก OneDrive เข้า repo หรือเมื่อ merge Pull Request — ให้อนุญาตตามที่ระบบถาม หรือรันคำสั่งที่ Claude ให้เอง และให้ผู้ดูแลกด merge

  • repo เป็น Public — Claude จะถามยืนยันก่อน push เอกสารภายใน

12. สร้าง GitHub Token และเพิ่มหมวดหมู่

Token (ทำครั้งเดียว ต่อผู้ใช้): GitHub › Settings › Developer settings › Fine-grained personal access tokens › Generate new token — Repository access เลือกเฉพาะ repo PCCkm และ Permissions: Contents → Read and write จากนั้นกด "เข้าสู่ระบบ" บนเว็บ ใส่ชื่อที่แสดงและ Token (ระบบจำไว้ในเบราว์เซอร์เครื่องนั้น ไม่ควรแชร์ และควรออกจากระบบเมื่อใช้เครื่องร่วมกัน)

เพิ่มหมวดหมู่: ปุ่ม "+ เพิ่มหมวดหมู่" ใต้เมนูซ้าย เลือกหมวดแม่ได้ทุกระดับ แต่แก้ชื่อหรือลบหมวดจากหน้าเว็บไม่ได้ (ต้องแก้ไฟล์ข้อมูลผ่านผู้ดูแล) หมวดใหม่ของฐานความรู้ต้องเพิ่มในตารางจับคู่ของ tools/check_sync.pl และ tools/sync_from_onedrive.pl กับตารางใน 00_INDEX.md ด้วย

13. แก้ปัญหาเบื้องต้น

  • "Token ไม่ถูกต้อง หรือหมดอายุ" — สร้าง Token ใหม่ตามข้อ 12 แล้วเข้าสู่ระบบอีกครั้ง
  • GitHub API error (403) หรือ (404) ตอนบันทึก — Token ไม่มีสิทธิ์เขียน repo นี้ ตรวจว่าเลือก repo PCCkm และตั้ง Contents เป็น Read and write
  • GitHub API error (409) หรือ (422) — มีคนแก้พร้อมกัน หรือมีไฟล์ชื่อเดียวกันในเวอร์ชันเดียวกันอยู่แล้ว ให้รีเฟรชหน้า ตรวจว่าเอกสารถูกบันทึกไปหรือยัง แล้วลองใหม่ (ถ้าซ้ำ ให้เปลี่ยนชื่อไฟล์)
  • บันทึกเอกสารใน Knowledge Management ไม่ได้ — ตรวจว่าแนบไฟล์ .md (นามสกุล .md หรือ .markdown) และใส่ Tag รหัส BM-xxx-nnn ถูกรูปแบบ
  • เพิ่มเอกสารแล้วเปิดไฟล์ไม่ได้ (404) ชั่วคราว — ไฟล์มาจากเว็บที่ deploy รอบละประมาณ 1 นาที รอแล้วรีเฟรช
  • check_sync รายงานความต่าง — อ่านรายการที่แจ้ง (ขาดแถวสารบัญ / ไฟล์ต่างกัน / ชื่อไม่ตรง) แล้วแก้ฝั่งที่ล้าหลังตามข้อ 6

14. โฟลเดอร์ Paradigm บน OneDrive

  • ตำแหน่ง: Business Management/Paradigm/ จัดเป็นโฟลเดอร์ตามกลุ่มและหมวดบนเว็บ (G1 Strategy, G2 STEM & DBTP, G4 Business Mgmt/...) ใช้ชื่อไฟล์เดิม
